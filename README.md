# Frostfall — RTS Survival Game

A real-time strategy survival game developed in **Unity 6** as a Master's Final Project (TFM). Players build and manage a base, recruit units, and defend against escalating enemy waves in a harsh winter environment. Survive all waves to achieve victory; lose your Command Post and the game is over.

---

## Features

- **Base building system** — place and construct multiple building types with resource cost validation, NavMesh placement restrictions, and fog-of-war constraints
- **Unit recruitment** — train units at barracks-type buildings with a queue system
- **Wave-based enemy system** — procedurally scaled enemy hordes with 6 enemy types (Walker, Runner, Heavy, Harpy, Fatty, Spitter), difficulty-adjusted per wave
- **Resource management** — six resource types (Food, Wood, Stone, Iron, Electricity, Population) generated by production buildings placed on resource zones
- **Combat system** — melee, ranged (shoot), area-of-effect, and throw attack types; dedicated healing units
- **Patrol & AI** — units can patrol between waypoints; enemies navigate via NavMesh with behaviour trees
- **Fog of War** — orthographic render-texture approach; units and buildings outside player vision are hidden
- **Day / Night cycle** — visual blizzard effect triggers at wave start; snow effect during rest phase
- **Minimap** — clickable minimap for rapid camera navigation
- **Full audio system** — AudioMixer-based with background music, horde music, per-unit selection/movement audio, and building/combat SFX
- **Main menu & options** — quality settings, volume controls, difficulty selector
- **Pause menu, victory screen, and defeat screen**
- **Multiple difficulty modes** — Easy, Medium, Hard, Infinite

## Architecture Overview

### Event System

All inter-system communication is handled via **ScriptableObject-based events** (`GameEvent<T>`). Each event type is a concrete subclass (e.g. `UnitSelectedEvent`, `ResourceEvent`) stored as a project asset. Components subscribe in `Awake` and unsubscribe in `OnDestroy`, keeping systems fully decoupled.

### Entity Hierarchy

```
CommonActions  (abstract MonoBehaviour — selection, health, death, visibility, actions)
├── BaseUnit   (+ NavMeshAgent + BehaviorGraphAgent — movement, healing)
│   └── EnemyController
└── BaseBuilding  (construction, repair, resource refund on destroy)
    ├── ProductionBuilding   — generates resources over time
    ├── RecruitBuilding      — trains units with a queue
    ├── AttackerBuilding     — defensive turrets
    ├── BuilderBuilding      — constructs other buildings
    └── ExplodingBuilding    — triggers explosion on destruction
```

### Action System

Unit and building capabilities are defined as **ScriptableObject** assets derived from `BaseAction`. Each entity carries an `Actions[]` array that the UI reads to generate buttons. Actions validate execution via `CanExecute` / `Blocked`, and building placement via `Restriction[]` (NavMesh, physics overlap, resource zone, fog-of-war checks).

### Behaviour Trees

Unit and building AI runs through **Unity Behavior** graphs. C# scripts communicate intent by setting named variables on `BehaviorGraphAgent`:

- Units: `"UnitActions"` (Stop / Move / Attack / Patrol / Heal / Repair)
- Buildings: `"BuildingActions"` (Build / Repair / Attack / etc.)

### Game Loop

`GameManager` drives the wave cycle:

1. **Rest phase** — countdown progressbar; snow effect active
2. **Wave phase** — blizzard effect; `EnemySpawner` spawns enemies scaled to wave number and difficulty
3. **Wave cleared** — all enemies dead → next wave begins
4. **Victory** — all waves survived
5. **Defeat** — Command Post (`"CommandPost"` tag) destroyed

Difficulty is persisted via `PlayerPrefs` key `"dificultyMode"` and scales `timeBetweenWaves` and enemy count multipliers.

## Game Mechanics

### Resources

| Resource | Generated by | Used for |
|---|---|---|
| Food | Farm / Greenhouse | Units, buildings |
| Wood | Sawmill | Buildings |
| Stone | Quarry | Buildings |
| Iron | Iron Mine | Advanced units & buildings |
| Electricity | Electric Generator | Certain buildings (consumed) |
| Population | Housing | Unit cap |

Resource buildings must be placed on matching `ResourceArea` zones visible on the terrain.

### Units

Player units are recruited at barracks. Each unit has a `SO_BaseUnit` ScriptableObject defining its name, icon, health, generation time, resource cost, vision range, and audio clips.

Key unit roles:
- **Soldier** — basic melee/ranged combatant
- **Hunter** — ranged thrower
- **Doctor** — healer unit

### Enemy Types

| Type | Role |
|---|---|
| Walker | Standard melee |
| Runner | Fast melee |
| Heavy | Tanky melee |
| Harpy | Special |
| Fatty | Special |
| Spitter | Ranged special |

Special enemies appear with increasing probability as waves progress (capped at 25% chance).

### Building Placement

While a `BuildBuildingAction` is active, a preview ghost is rendered with green (valid) or red (invalid) materials. Validity is checked against all `Restriction` assets on the action: NavMesh coverage, physics overlaps with blocked layers, required resource zone type, and fog-of-war visibility.

## How to Run

1. Open the project in **Unity Hub** using Unity **6000.3.8f1**.
2. Open `Assets/Scenes/Menu.unity` for the main menu, or `Assets/Scenes/Game.unity` to jump directly into gameplay.
3. Press **Play** in the Unity Editor.

For a standalone build: `File > Build Settings`, select your target platform, and click **Build**.

> There is no separate CLI build process — compilation and builds are managed entirely through the Unity Editor.
